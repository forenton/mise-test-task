# MISE Booking API

REST API для онлайн-бронирования столика в ресторане.

## Стек

- Python 3.11+
- FastAPI
- Pydantic v2
- SQLAlchemy 2.0 async
- SQLite через aiosqlite
- Uvicorn
- Poetry
- pytest + httpx
- Docker Compose

## Запуск локально

Установить зависимости:

```bash
poetry install
```

Запустить приложение:

```bash
poetry run uvicorn app.main:app --reload
```

API будет доступно на `http://127.0.0.1:8000`.

Документация FastAPI:

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

По умолчанию приложение использует SQLite-файл `bookings.db` в корне проекта. Путь к БД можно изменить переменной окружения `APP_DATABASE_URL`.

## Запуск через Docker Compose

```bash
docker compose up --build
```

API будет доступно на `http://127.0.0.1:8000`.

В Docker Compose данные SQLite сохраняются в volume `booking_data`.

## Тесты

```bash
poetry run pytest
```

## Принятые решения

Я выбрал SQLite с async SQLAlchemy 2.0, потому что это ближе к реальному backend-проекту и при этом не требует внешней базы данных. Приложение разделено на слои: роуты отвечают за HTTP-контракт, Pydantic-схемы - за валидацию входных и выходных данных, сервис - за бизнес-логику. Таблицы создаются при старте через `metadata.create_all`; в production-проекте я бы заменил это на Alembic-миграции. Занятость слота проверяется только среди активных броней, поэтому после отмены тот же слот можно забронировать снова.

## Что бы доделал при наличии времени

- Добавил Alembic-миграции.
- Добавил уникальное ограничение для активных броней на уровне БД.
- Расширил тесты на пограничные даты, форматы имени и пагинацию.
- Добавил структурированное логирование.

## Эндпоинты

| Метод | Путь | Описание |
| --- | --- | --- |
| `POST` | `/bookings` | Создать бронь. Возвращает `201` и созданную бронь. |
| `GET` | `/bookings` | Получить список броней. Поддерживает фильтр `?date=YYYY-MM-DD`, `limit`, `offset`. |
| `GET` | `/bookings/{id}` | Получить бронь по id. Если бронь не найдена, возвращает `404`. |
| `DELETE` | `/bookings/{id}` | Отменить бронь. Запись не удаляется, статус меняется на `cancelled`. |

## Формат брони

```json
{
  "name": "Анна Иванова",
  "phone": "+79991234567",
  "booking_date": "2026-09-10",
  "booking_time": "19:00",
  "guests": 4
}
```

Ответ содержит те же поля, а также `id` и `status`:

```json
{
  "name": "Анна Иванова",
  "phone": "+79991234567",
  "booking_date": "2026-09-10",
  "booking_time": "19:00:00",
  "guests": 4,
  "id": 1,
  "status": "active"
}
```

## Правила валидации

- `name` - минимум 2 символа, только буквы, пробелы и дефис.
- `phone` - российский формат: `+7XXXXXXXXXX` или `8XXXXXXXXXX`.
- `booking_date` - не раньше сегодняшнего дня и не позднее 90 дней от текущей даты.
- `booking_time` - только часовые слоты с `12:00` до `22:00`.
- `guests` - целое число от 1 до 12.

Ошибки валидации возвращаются стандартным ответом FastAPI/Pydantic с кодом `422`.

## Ошибки

| Ситуация | Код | Ответ |
| --- | --- | --- |
| Бронь не найдена | `404` | `{"detail": "Бронь не найдена"}` |
| Активная бронь на выбранные дату и время уже существует | `409` | `{"detail": "Дата и время бронирования уже занята"}` |
| Невалидные входные данные | `422` | Стандартный формат FastAPI |
